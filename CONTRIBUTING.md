# How to contribute to goldmark

This project is maintained by one person as a personal hobby project and is provided **free of charge**. Please keep this in mind when opening issues or proposing changes. The maintainer has limited time and capacity to review contributions.

## Questions and Ideas

If you have a question, suggestion, or idea for the project, please use **GitHub Discussions** rather than opening an Issue.

## Reporting Issues

If you have found a bug or another concrete problem with the project, please open an **Issue**.

When creating an Issue, **you must follow the appropriate Issue Template** and provide the requested information. Issues that do not follow the template may not be reviewed.

### Please Do Not Mass-Submit AI-Generated Issues

You are welcome to use AI tools to investigate this project, identify potential problems, or explore possible improvements. **How you use AI for your own investigation is entirely up to you.**

However, please do **not** turn the results of large-scale AI-assisted investigations into a large number of GitHub Issues.

This project is maintained by one person as a **free hobby project**, and there is no dedicated team available to review a large volume of issues. Every Issue requires time and effort to understand, reproduce, verify, and respond to.

If you use AI to identify potential issues, please use your own judgment to determine which findings are genuinely worth reporting. A small number of well-understood, short, high-quality Issues is much more helpful than dozens or hundreds of automatically AI generated long reports.

If you use AI to identify a large number of potential issues, you are welcome to apply fixes(by AI) for those issues to your own fork and use that fork for your own project. You do not need to mass-submit those AI-generated findings as Issues to this project.

In short:

- **Using AI to find problems:** Completely fine.
- **Investigating the project extensively with AI:** Completely fine.
- **Submitting a large number of AI-generated findings as Issues:** Please don't.

## Extensions

If you have created an extension for this project, please leave a comment on the **[Gist](https://gist.github.com/yuin/5b9a84859c00e5b39cee8cbabe1e6169)**

The maintainer will review the information and add it to the Gist.

The contents of the Gist are periodically imported into the project's README automatically using GitHub Actions.

Please do not open a separate Issue or Pull Request just to add an extension to the list.

## Pull Requests
At this time, Pull Requests are limited to **collaborators**.

This policy is largely due to the high volume of AI-generated Pull Requests received by the project.

If you would like to contribute a change, you are welcome to fork the repository, make your changes, and share the relevant information or patch in an Issue instead.

Please keep in mind that the same guideline regarding AI-generated Issues applies here: **please do not turn the results of AI-assisted work into a large number of Issues.**

### Why Are Pull Requests Restricted?

A significant proportion of the AI-generated Pull Requests received so far have not been suitable for merging.

In many cases, the proposed changes:

- Addressed only a specific symptom with an ad-hoc workaround rather than addressing the underlying problem
- Introduced changes that were inconsistent with the existing design or implementation
- Applied different approaches to similar problems without a consistent rationale
- Required substantial additional work to review, correct, or rewrite
- Appeared to have been generated without sufficient understanding of the existing codebase

There have also been many submissions that were essentially **AI slop**: large amounts of low-value, unnecessary, or poorly considered changes generated by AI.

This is not a criticism of using AI itself. AI can be a useful tool for investigating problems, exploring solutions, and writing code.

The problem is that reviewing AI-generated contributions that have not been sufficiently understood or validated by their authors can require a significant amount of maintainer time.

If you are going to use AI to work on this project, please make sure that you understand the proposed changes and have personally reviewed, validated and summarized them before submitting anything.
