# Package `parser` Documentation: `parser/parser.go`

## Overview

The `parser/parser.go` file contains the core engine for parsing Markdown text into an Abstract Syntax Tree (AST). It provides the core parsing architecture for Goldmark, defining interfaces and concrete implementations for:

- **Block Parsing**: Process structural elements such as headings, lists, code blocks, and blockquotes line-by-line.
- **Inline Parsing**: Process character-level elements such as links, code spans, emphasis, and raw HTML within blocks.
- **Context Management**: Track contextual state throughout the parsing process (e.g., link definitions, opened container blocks, element IDs, delimiter lists).
- **ID Generation**: Generate unique element IDs (e.g., for heading anchors).
- **Transformers**: Modify AST nodes after block parsing (`ParagraphTransformer`) or after the document AST is completely built (`ASTTransformer`).

---

## Core Interfaces

### `Parser`
The main entrance interface for parsing Markdown source text into an AST `ast.Node`.

```go
type Parser interface {
    Parse(source []byte, opts ...ParseOption) ast.Node
    ParseStringSource(source string, opts ...ParseOption) ast.Node
}
```

- **`Parse(source []byte, opts ...ParseOption) ast.Node`**: Parses a raw byte slice into an AST root node (`ast.Document`).
- **`ParseStringSource(source string, opts ...ParseOption) ast.Node`**: Helper that converts a string to a read-only byte slice without allocation and calls `Parse`.

---

### `BlockParser`
Interface for parsing block-level elements (e.g., Paragraphs, Headings, Lists, Blockquotes).

```go
type BlockParser interface {
    Trigger() []byte
    Open(parent ast.Node, reader text.Reader, pc Context) (ast.Node, State)
    Continue(node ast.Node, reader text.Reader, pc Context) State
    Close(node ast.Node, reader text.Reader, pc Context)
    CanInterruptParagraph() bool
    CanAcceptIndentedLine() bool
}
```

- **`Trigger()`**: Returns character triggers for opening the block. If `nil`, `Open` is called for any line.
- **`Open(...)`**: Parses the current line to open a new block node. Returns the node and a `State`.
- **`Continue(...)`**: Evaluates whether an open block continues on the current line.
- **`Close(...)`**: Executed when a block parser transitions to a closed state.
- **`CanInterruptParagraph()`**: Returns `true` if this block parser can interrupt an active paragraph.
- **`CanAcceptIndentedLine()`**: Returns `true` if it can open a node when indented more than 3 spaces.

---

### `InlineParser`
Interface for parsing inline-level elements within blocks (e.g., Code Spans, Links, Emphasis).

```go
type InlineParser interface {
    Trigger() []byte
    Parse(parent ast.Node, block text.Reader, pc Context) ast.Node
}
```

- **`Trigger()`**: Returns trigger characters (punctuation or spaces) that initiate inline parsing.
- **`Parse(...)`**: Parses text into an inline AST node and advances the reader position.

---

### `Context`
An interface representing the state carried through the parse operation.

Key functionalities provided by `Context`:
- **Key-Value Store**: Custom context key access via `Get`, `Set`, and `ComputeIfAbsent`.
- **Link Reference Definitions**: Managing `LinkDefinition` mappings (`AddLinkDefinition`, `LinkDefinition`, `LinkDefinitions`).
- **Element IDs Tracking**: Accessing the `IDs` tracker (`IDs()`).
- **Block Offsets & Indents**: Managing line indentation offsets (`BlockOffset`, `BlockIndent`).
- **Delimiter Lists**: Managing inline delimiter linked lists (`FirstDelimiter`, `LastDelimiter`, `PushDelimiter`, `RemoveDelimiter`, `ClearDelimiters`).
- **Opened Blocks Stack**: Tracking container blocks currently being processed (`OpenedBlocks`, `SetOpenedBlocks`, `LastOpenedBlock`).
- **Link Label State**: Checking `IsInLinkLabel()`.

---

### `IDGenerator` and `IDs`

#### `IDGenerator` Interface
```go
type IDGenerator interface {
    Generate(value []byte, kind ast.NodeKind) []byte
}
```
Generates base string IDs given node content and its kind (`ast.NodeKind`).

#### `IDs` Struct
Tracks assigned element IDs across a single parse session to ensure uniqueness.
```go
type IDs struct {
    values    map[string]bool
    generator IDGenerator
}
```
- **`Generate(value []byte, kind ast.NodeKind) []byte`**: Generates a unique ID. If the base ID generated by `IDGenerator` is already present in `values`, numeric suffixes (e.g., `-1`, `-2`) are appended until a unique ID is found.
- **`Put(value []byte)`**: Manually registers an ID as used.

#### `defaultIDGenerator`
The built-in implementation of `IDGenerator`. It strips non-alphanumeric/non-space/non-hyphen characters, converts uppercase ASCII to lowercase, and replaces spaces/underscores with hyphens. Defaults to `"heading"` for heading nodes or `"id"` for others if the result is empty.

---

### `LinkDefinition`
Represents a Markdown link reference definition.

```go
type LinkDefinition interface {
    String() string
    Label() []byte
    Destination() []byte
    Title() []byte
}
```
Constructed via `NewLinkDefinition(label, destination, title []byte)` or internally from an `ast.LinkReferenceDefinition` node using `newLinkDefinitionFromNode`.

---

### `ParagraphTransformer` & `ASTTransformer`

- **`ParagraphTransformer`**: Performs transformations on parsed paragraph nodes before inline parsing occurs (e.g., extracting link reference definitions).
  ```go
  type ParagraphTransformer interface {
      Transform(node *ast.Paragraph, reader text.Reader, pc Context)
  }
  ```
- **`ASTTransformer`**: Operates on the full `ast.Document` tree after block and inline parsing are completed.
  ```go
  type ASTTransformer interface {
      Transform(node *ast.Document, reader text.Reader, pc Context)
  }
  ```

---

### `CloseBlocker` & `Extension`

- **`CloseBlocker`**: A callback interface triggered when a block node is closed during inline parsing.
  ```go
  type CloseBlocker interface {
      CloseBlock(parent ast.Node, block text.Reader, pc Context)
  }
  ```
- **`Extension`**: Interface for grouping functional options together into extension packages.
  ```go
  type Extension interface {
      ParserOptions(*Config) []Option
  }
  ```

## Constants and Enums

### `State` Flags
`State` is an integer bitmask used by `BlockParser` methods (`Open`, `Continue`) to signal state to the parser loop.

| Constant Flag | Value | Description |
| :--- | :--- | :--- |
| `None` | `0` | Zero-value state; no flags set. |
| `Continue` | `1 << 0` | Parser can continue parsing current block. |
| `Close` | `1 << 1` | Current block parsing is complete and should close. |
| `HasChildren` | `1 << 2` | Block may contain child block elements. |
| `NoChildren` | `1 << 3` | Block does not contain child blocks. |
| `RequireParagraph` | `1 << 4` | Requires the last node to be a paragraph (not converted/transformed). |

### Package Level Variables

- **`Nil`**: An `ast.Text` node representing an empty node. When returned by an inline parser, it indicates parsing succeeded without inserting a node into the AST.
- **`ContextKeyMax`**: Tracks the highest assigned integer context key index. Updated via `NewContextKey()`.
- **`CommonMark`**: Pre-instantiated `Extension` that provides standard CommonMark block parsers, inline parsers, and paragraph transformers.

## Main Parsing Architecture & Lifecycle

When `Parser.Parse(source, opts...)` is called, execution proceeds through distinct stages:

```
                  ┌────────────────────────┐
                  │      Parse(...)        │
                  └───────────┬────────────┘
                              │
                    (Lazy Initializer)
                    p.initSync.Do(...)
                              │
                              ▼
                   ┌──────────────────────┐
                   │    parseBlocks()     │
                   └──────────┬───────────┘
                              │
                              ▼
                   ┌──────────────────────┐
                   │     walkBlock()      │
                   │    (parseBlock)      │
                   └──────────┬───────────┘
                              │
                              ▼
                   ┌──────────────────────┐
                   │   astTransformers    │
                   └──────────┬───────────┘
                              │
                              ▼
                   ┌──────────────────────┐
                   │  ast.Document Return │
                   └──────────────────────┘
```

### 1. Lazy Initialization
On first use (`p.initSync.Do`), the parser:
- Sorts block parsers, inline parsers, paragraph transformers, and AST transformers according to their priorities.
- Indexes block parsers and inline parsers by trigger byte ASCII indexes (`[256][]BlockParser` and `[256][]InlineParser`). Parsers with no trigger bytes are moved into `freeBlockParsers`.
- Initializes text decoders according to `EscapedSpace` configuration settings.

### 2. Block Parsing (`parseBlocks`)
- Loops through input lines via `text.Reader`.
- Calls `openBlocks(...)` to identify new container/leaf blocks or continuation of existing blocks using `BlockParser.Open()` and `BlockParser.Continue()`.
- Tracks opened blocks in the `Context` stack (`OpenedBlocks`).
- When blocks close, `closeBlocks(...)` invokes `BlockParser.Close()` and applies registered `ParagraphTransformer` instances to any closed paragraphs.

### 3. Inline Parsing (`walkBlock` / `parseBlock`)
- Traverses the generated block-level AST using `walkBlock`.
- For each block node containing source segment references, `parseBlock` scans characters sequentially:
  - Looks up registered `InlineParser` instances matching the trigger character.
  - Executes matching inline parsers to extract inline elements (code spans, links, emphasis, etc.).
  - Collects text segments into `ast.Text` nodes.
- Calls `ProcessDelimiters(nil, pc)` to resolve inline delimiter structures (e.g., emphasis tags, links).
- Invokes all registered `CloseBlocker.CloseBlock` callbacks.

### 4. AST Transformation
- Iterates over sorted `ASTTransformer` implementations to modify the finalized `ast.Document`.

### 5. Pretty Print Output (Optional)
- If `WithPrettyPrint` option was provided, prints the AST dump to stdout or specified writer.

## Configuration and Options

### Functional Parser Options (`Option`)

| Functional Option | Description |
| :--- | :--- |
| `WithAttribute()` | Enables support for custom element attributes on headings and blocks. |
| `WithDefaultParsers(v bool)` | Enables or disables the standard CommonMark default parsers. |
| `WithExtensions(ext ...Extension)` | Attaches syntax extensions to the parser configuration. |
| `WithBlockParsers(bs ...)` | Registers prioritized `BlockParser` implementations. |
| `WithInlineParsers(is ...)` | Registers prioritized `InlineParser` implementations. |
| `WithParagraphTransformers(ps ...)`| Registers prioritized `ParagraphTransformer` implementations. |
| `WithASTTransformers(ps ...)` | Registers prioritized `ASTTransformer` implementations. |
| `WithEscapedSpace()` | Configures decoder so backslash-escaped spaces (`\ `) do not trigger parsers. |
| `WithIDGenerator(gen)` | Sets a custom `IDGenerator`. |

### Execution Options (`ParseOption`)

Passed directly to `Parser.Parse(source, opts...)`:

- **`WithContext(ctx Context)`**: Supplies a custom context object for state tracking during parsing.
- **`WithPrettyPrint(opts ...ast.PrettyPrintOption)`**: Pretty-prints the resulting AST to standard output for debugging.
